# Implementation Plan: Study Guide & Question Bank

**Branch**: `002-study-guide-question-bank` | **Date**: 2026-07-04 | **Spec**: [spec.md](./spec.md)

## Summary

Build a content-driven study guide and question bank on top of the existing Next.js static site. Approximately 170 questions and one guide already exist as Markdown/YAML files in `content/`. A TypeScript content loader parses these at build time into typed data structures, validates all cross-references, and feeds four static Next.js pages: study index, guide viewer, question bank (with client-side search/filter), and individual question pages. Assets in `content/assets/` are copied to `public/images/` before the Next.js build. A "Study" link is added to the existing site nav.

## Technical Context

**Language/Version**: TypeScript 5.x / Node.js ≥20.9  
**Primary Dependencies**: Next.js 16.x (App Router, `output: 'export'`), React 19.x, Tailwind v4 — plus new: `gray-matter`, `unified`, `remark-parse`, `remark-rehype`, `rehype-stringify`, `rehype-sanitize`, `js-yaml`, `zod`, `vitest`  
**Storage**: Flat files in `content/` (no database)  
**Testing**: `vitest`  
**Target Platform**: Static export (CDN / Vercel)  
**Project Type**: Next.js static web application  
**Performance Goals**: Client-side search returns results instantly for ≤500 questions; full build (including content validation and asset copy) completes within 60 seconds  
**Constraints**: `output: 'export'` — no runtime filesystem access from client components; no API routes; all data resolved at build time  
**Scale/Scope**: ~170 questions now, hundreds anticipated; ~5–10 guides

### Implementation Sequence

Tasks should be implemented in this order to respect dependencies:

#### Step 1 — Install dependencies

```bash
npm install gray-matter unified remark-parse remark-rehype rehype-stringify rehype-sanitize js-yaml zod
npm install --save-dev @types/js-yaml vitest @vitest/ui
```

#### Step 2 — Asset copy script

Create `scripts/copy-content-assets.mjs`. Add `"prebuild": "node scripts/copy-content-assets.mjs"` to `package.json` scripts. The script uses `fs.cpSync('content/assets', 'public/images', { recursive: true })`.

#### Step 3 — Content loader library (`src/lib/content/`)

Implement in this order (each module depends on the previous):

1. `types.ts` — all TypeScript interfaces
2. `parse-tags.ts` — reads `content/tags.yml`, returns `TagMap`
3. `parse-question.ts` — reads one `.md` file, returns `Question`; validates ID, tags, required sections
4. `parse-guide.ts` — reads one `.yml` guide file, returns `RawGuide`; validates structure
5. `validate.ts` — resolves `RawGuide` → `Guide` by looking up question IDs; fails on unknown IDs and duplicate IDs within a guide
6. `search-index.ts` — strips HTML from `Question[]` to produce `QuestionSearchIndexEntry[]`
7. `loader.ts` — orchestrates all of the above; exposes `loadContent(): ContentLibrary`

#### Step 4 — Tests (`tests/lib/content/`)

Write tests for:

- `parse-question.test.ts`: valid question, multiline question with code block, with/without instructor notes, with/without sources, with image reference, missing `### Question`, missing `### Answer`, duplicate IDs, filename mismatch, non-kebab-case ID, unknown tag
- `parse-guide.test.ts`: valid guide, chapter/section/question order preserved, missing question ID, duplicate guide slug, no chapters, no sections, no questions, same question in two guides (allowed), same question twice in one guide (fails)
- `parse-tags.test.ts`: valid tags.yml, missing file, non-kebab-case key, missing label
- `search-index.test.ts`: index built correctly, search matching title/question text/answer/tags/sources

#### Step 5 — Study pages

1. `src/app/study/page.tsx` — brief intro sentence + guide list + "Browse all questions" link
2. `src/app/study/guides/[slug]/page.tsx` — `generateStaticParams` + full guide renderer with collapsible answers and optional instructor notes disclosure; print-friendly styles
3. `src/app/study/questions/page.tsx` + `_components/QuestionSearch.tsx` — server component passes `QuestionSearchIndexEntry[]` as prop to client component; client handles search + tag filter UI
4. `src/app/study/questions/[slug]/page.tsx` — `generateStaticParams` + individual question page

#### Step 6 — Site nav update

Add "Study" link to `src/app/_components/SiteNav.tsx` pointing to `/study`.

#### Step 7 — Build integration

- Verify `npm run build` runs `prebuild` (asset copy) before `next build`
- Verify `next build` output includes all study pages in `out/`
- Verify `verify:no-booking-link` script still passes

### Key Design Decisions

**Section extraction from question Markdown**

The remark AST is walked to identify `### Heading` nodes. Content between consecutive headings is collected into slices:

```
Heading "Question"         → questionSlice  (required)
Heading "Answer"           → answerSlice    (required)
Heading "Instructor notes" → notesSlice     (optional)
Heading "Sources"          → sourcesSlice   (optional)
Heading <anything else>    → build error
```

Each slice is converted to HTML independently via `remark-rehype` + `rehype-stringify`. Image src attributes matching `../assets/` are rewritten to `/images/` during the pipeline.

**Collapsible answers on guide pages**

Use the native HTML `<details>`/`<summary>` element for keyboard-accessible disclosure without JavaScript. "Show answer" → `<summary>Show answer</summary>`. Print CSS: `details { display: block } details > * { display: block }` forces answers visible when printing.

**Instructor notes disclosure**

Same `<details>`/`<summary>` pattern. Only rendered when `instructorNotesHtml` is present; nothing output when absent.

**Tag filter UI on question bank**

Tag filters rendered as `<button>` elements with `aria-pressed` state. Active tags visually distinguished. "Clear filters" resets both search text and active tags.

**Static params generation**

`/study/guides/[slug]/page.tsx` calls `generateStaticParams()` → returns `guide.slug` for each guide in `content/guides/`. `/study/questions/[slug]/page.tsx` returns `question.slug` for each question in `content/questions/`.

**Build failure messaging**

Zod validation errors include `.path` (field path) and `.message`. The content loader prefixes every error with the source file path:

```
Error in content/questions/safety-pilot-logging.md: missing required section "### Answer"
Error in content/guides/instrument-rating-oral.yml: unknown question id "nonexistent-question"
```

If any validation error is found, the loader throws an aggregated error listing all problems, which causes `next build` to exit non-zero.

## Contracts

The content loader exposes one public interface consumed by all study pages:

```typescript
// src/lib/content/loader.ts

export type ContentLibrary = {
  questions: Question[]; // all questions, sorted by id
  questionMap: Record<string, Question>;
  guides: Guide[]; // all guides (chapters + questions resolved)
  guideMap: Record<string, Guide>;
  tags: TagMap;
  searchIndex: QuestionSearchIndexEntry[];
};

export function loadContent(): ContentLibrary;
```

Pages call `loadContent()` in Server Component scope (never in client components). The function reads the filesystem and throws on any validation error, failing the build.
